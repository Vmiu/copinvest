## 1. System Classification

**System Type:** Conversational (Hybrid — RAG-augmented agent with tool use)

**Description:**
A prompt-driven agent that accepts freetext messages from HK investment advisers and routes them to the appropriate workflow (QA/brief/follow-up/chat) using LLM tool-calling. The agent wraps the existing RAG pipeline as a `search_rag` tool, returns source-attributed answers with `[N]` citations, asks clarifying questions when information is missing, and transparently reports search results. Every tool invocation is logged for audit compliance.

**Critical Failure Modes:**
1. Agent fabricates claims not grounded in retrieved documents (hallucination beyond RAG context)
2. Agent fails to cite sources — adviser acts on unsourced advice, violating SFC compliance requirements
3. Tool call loop exceeds max turns or enters infinite loop, blocking advisers from getting answers
4. `search_rag` tool returns documents above adviser's sensitivity tier (RBAC bypass)
5. Audit trail missing tool-call records — compliance investigation cannot reconstruct agent decision path

## 2. Framework Decision

**Selected Framework:** OpenAI Python SDK v1.68+ (No Agent Framework)

**Version:** openai >=1.68.0 (existing project dependency)

**Rationale:**
The project already uses the OpenAI Python SDK via OpenRouter for DeepSeek V4 Pro. The OpenAI SDK's native function/tool-calling support (`client.chat.completions.create(…, tools=[…])`) provides everything needed for the Phase 8 agent loop without adding an agent framework. v2.0's LangGraph attempt was abandoned as "messy/unsatisfying." A prompt-driven `while not done` loop with explicit tool dispatch is simpler, more debuggable, and sufficient for the max-5-turn requirement. No new dependencies.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LangGraph | v2.0 attempt was "messy/unsatisfying." Overhead of graph mental model not justified for simple tool-calling loop with max 5 turns. |
| OpenAI Agents SDK | Vendor lock-in to OpenAI; project uses DeepSeek V4 Pro via OpenRouter, not OpenAI models directly. |
| CrewAI | Multi-agent orchestration is overkill for a single-agent tool loop. Adds complexity without proportional value. |
| Claude Agent SDK | Claude-only vendor lock-in; project uses DeepSeek models. |

**Vendor Lock-In Accepted:** Partial — OpenAI SDK API surface (tool-calling schemas) is the de facto industry standard supported by OpenRouter, DeepSeek, and most providers.
